## 类型和结构体

1. 问：为什么选择编译而非解释执行 C++ 代码？
> - 因为编译能让我们生成效率更高的机器码，解释器每次只能处理代码的一小部分，而编译器能看到全部代码。  
>
> - 不过，编译过程是需要耗费时间的！   
>
> **注**：编译是将源代码整体转换为机器码后再运行的过程，解释执行则是逐行/逐段读取源代码并实时转换为机器指令运行

2. C++ 是一种静态类型语言（而 Python 是动态类型语言），其中类型指的是变量的“类别”，C++ 自带多种内置类型，包括但不限于 `int`、`double`、`string`、`bool`、`size_t`（常用于表示“对象大小或索引”的无符号整数类型）
3. 静态类型（特性）：每个变量都必须声明类型；一旦声明，类型便不能更改
4. 为什么需要静态类型？

> - **“运行效率更高”**：静态类型在编译阶段已确定所有变量类型，无需像动态类型语言（如 Python）那样在运行时实时判断变量类型，减少了运行时的计算开销，因此程序执行速度更快
> - **“易理解和推导代码逻辑”**：变量声明时明确标注类型（如 C++ 中`int age`“年龄为整型”、`string name`“姓名为字符串型”），其他开发者阅读代码时无需猜测变量用途，分析代码流程、排查逻辑问题时更清晰
> - **“错误检查更完善”**：静态类型语言会在编译阶段主动检查类型不匹配等错误（例如将`double`类型的值赋值给`bool`类型变量），提前暴露问题，避免这类错误在程序运行时才爆发，降低调试成本

5. 函数重载是指定义两个名称相同但参数不同的函数

> 1. **参数个数不同**：例如定义`add(int a, int b)`（两个整型参数）和`add(int a, int b, int c)`（三个整型参数）
> 2. **参数类型不同**：例如定义`print(int num)`（参数为整型）和`print(double num)`（参数为双精度浮点型）
> 3. **参数类型顺序不同**：例如定义`swap(int a, double b)`（先整型后浮点型）和`swap(double a, int b)`（先浮点型后整型）

6. `std::pair` 从技术层面来说并非一种（具体）类型，而是一个模板，定义在头文件 `<utility>` 中；使用 pair 时，我们必须在 <> 符号内列出其 first 和 second 的类型，例如`std::pair<std::string, size_t>`

```c++
template <typename T1, typename T2>
struct pair {
	T1 first;
	T2 second;
};
std::pair<std::string, int>
```

7. `std` 是 C++ 标准模版库，C++ 提供了内置类型、函数及其他更多功能组件

> - **头文件与组件的对应关系**：`#include <xxx>` 是 C++ 引入标准库功能的核心语法，`<>` 内的是 “头文件”，其作用是声明对应的标准库组件（如 `<string>` 声明了 `std::string` 的用法），必须包含头文件才能使用这些组件，否则编译器会报错
> - **`std::` 的含义**：`std` 是 C++ 标准库的 “命名空间”（namespace），`::` 是 “作用域解析符”。给标准库名称加 `std::`，是为了明确 “这个名称来自标准库”，避免和程序员自己定义的同名内容冲突（比如自己写的 `string` 类和标准库的 `std::string`）
> - **`using namespace std;` 的风险**：该语句的作用是 “将 `std` 命名空间下的所有名称导入当前作用域”，看似省去了写 `std::` 的麻烦，但会导致 “命名污染”—— 若你自己定义了和标准库同名的组件（如 `string`、`cout`），编译器无法区分使用哪一个，从而引发歧义错误，这也是其被视为 “不良风格” 的核心原因

8. `using` 关键字：反复写出冗长的类型名会很繁琐，我们可以使用 `using` 关键字创建类型别名，例如：

```c++
// 传统方式
std::pair<bool, std::pair<double, double>> solveQuadratic(double a, double b, double c);

// 使用 using 关键字
using Zeros = std::pair<double, double>;
using Solution = std::pair<bool, Zeros>;
Solution solveQuadratic(double a, double b, double c);
```

> **注**：这种用法与 `typedef`（另一种创建类型别名的关键字）功能类似，但`using`的语法更直观，尤其在处理模板类型时灵活性更高，是现代 C++ 中更推荐的方式

9. `auto` 是用于 “类型自动推导” 的关键字，核心作用是让编译器根据变量的**初始化值**自行判断其类型，无需开发者手动声明，尤其适合简化复杂类型的书写，例如：

```c++
// 传统方式
std::pair<bool, std::pair<double, double>> result = solveQuadratic(a, b, c);

// 使用 auto 关键字
auto result = solveQuadratic(a, b, c);

// This is exactly the same as the above! 
// result still has type std::pair<bool, std::pair<double, double>>
// We just told the compiler to figure this out for us!

// auto 还可以用 for 循环遍历中
std::vector<int> vec { 1, 2, 3, 4 };
for (auto elem : vec) {
  std::cout << elem << " ";
}

// auto 还可以推断函数的返回类型
auto smeagol() {
  return 20;
}

// 甚至可以推断函数参数的类型
void borges(auto cuento) {
  std::cout << cuento << std::endl;
}

borges(std::string { "el sur" }); // auto deduced as `std::string`
```

**注**：`auto` 也是静态类型的，下面这种方式是不允许的：

```c++
auto i = 1; 	// int inferred
i = "hello!";	// ❌ Doesn't compile

// 这种情况也不行，因为 auto 无法判断这是一个 pair 还是 vector，或者用户自定义的某种类型
auto oops() {
  return { 106.0, 107.0 };
}
```
