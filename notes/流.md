## 流

1. 流是用于 C++ 的通用输入 / 输出抽象，而抽象的核心作用是提供统一接口，对于流而言，这一接口的用途就是实现数据的读取与写入

2. `std::cout` 流是 `std::ostream`（标准输出流类）的一个流实例，它代表标准输出流！`std::cout` 具备 ` std::basic_ostream`（基础输出流类型）的属性

3. `std::cin` 是控制台输入流！`std::cin` 流是 `std::istream` 的一个实例，而  `std::istream` 代表标准输入流！`std::cin` 具备`std::istream` 类型的属性

4. 输入流与输出流对比：

| 类型   | 含义                       | 继承                   | 举例                                | 运算符 |
| ------ | -------------------------- | ---------------------- | ----------------------------------- | ------ |
| 输入流 | 一种从数据源读取数据的方法 | 从std::istream继承而来 | 从控制台读取某些内容（std::cin）    | >>     |
| 输出流 | 一种将数据写入目的地的方法 | 从std::ostream继承而来 | 将某些内容输出到控制台（std::cout） | <<     |

4. `std::stringstream` 是一个**双向字符串流**，可以像操作 `std::cin`/`std::cout`  一样操作字符串，支持格式化输入输出，以及内部维护一个字符串缓冲区和位置指针

5. `>>` 是提取操作符/输入操作符，作用是从输入流中提取数据，方向为数据从流“流向”变量

示例如下：

```c++
std::stringstream ss("Hello World 123");
std::string word1, word2;
int number;

// 用法：stream >> variable

ss >> word1;    // word1 = "Hello"
ss >> word2;    // word2 = "World"  
ss >> number;   // number = 123

// 注：>> 运算符只读取到下一个空白字符（空格、制表符、换行符）为止！
```

6. `<<` 是插入操作符/输出操作符，作用是向输出流中插入数据，方向为数据从变量“流向”流

示例如下：

```c++
std::stringstream ss;
ss << "Hello" << " " << "World" << " " << 123;
// ss现在包含 "Hello World 123"

// 用法：stream << data
std::cout << "Result: " << ss.str() << std::endl;
```

> **注**：流内部维护一个读取位置指针。每次使用 `>>` 操作符进行读取时，指针会自动移动到下一个未读位置，确保下次读取从当前指针位置继续，而不会重头开始。此外，`>>` 操作符会自动跳过空格、制表符、换行符等空白字符

7. `std::getline(istream& is, string& str, char delim)` 是一个函数，用来从流中读取一整行文本（直到遇到换行符或指定的分隔符）

- `getline ()` 读取输入流 is，直到遇到分隔符字符为止，并将其存储在某个缓冲区 `str` 中
- 分隔符字符默认是`‘\n’`（即换行符）
- `getline ()` 函数会读取并丢弃分隔符字符(比如默认分隔符是‘\n’（换行符）时，`getline ()` 读取完一行内容后，会把换行符也读取并丢弃，避免后续输入操作受残留换行符影响)

> **注**：如果 `getline()` 没有遇到分隔符，它会读取到流的末尾

8. 输出流中的字符会先存储在**中间缓冲区（intermediary buffer）**中，之后再被**刷新（flush）**到目标设备

> - 中间缓冲区的作用是暂存待输出的字符，避免程序频繁与目标设备（如控制台、文件）直接交互，从而提升 IO 操作效率；刷新是 IO 流中的关键操作，指将缓冲区中暂存的数据一次性写入到目标设备的过程（例如调用`std::flush`函数或遇到换行符`\n`时，会触发缓冲区刷新）
> - 刷新（操作）是一项开销大的操作

9. `std::cout` 流是**行缓冲的（line-buffered）**；缓冲区中的内容在发生**显式刷新（explicit flush）**前，不会显示在外部输出目标上

> - **行缓冲**：是 std::cout 的默认缓冲模式，将待输出的字符先暂存到一块内存缓冲区中，**不会立即输出到控制台**，特点是除显式刷新外，当遇到换行符 `\n` 时也会自动触发缓冲区刷新（即将内容输出到外部目标，如控制台）
> - **显式刷新**：指通过代码主动触发刷新操作，例如调用`std::flush`函数（`std::cout << std::flush;`）或使用`std::endl`（`std::cout << "内容" << std::endl;`，`endl`会同时完成换行和显式刷新，等价于`\n` + `std::flush`（先换行，再刷新））
> - **external source**：此处特指 std::cout 对应的实际输出设备，通常是电脑控制台（终端窗口）
> - 当缓冲区存储的字符数量达到其最大容量（不同系统 / 编译器可能不同，通常是几百字节）时，也会自动刷新
> - 当程序执行到`main`函数结束或调用`exit()`时，所有未刷新的缓冲区会被自动刷新，确保内容输出完整
> - **全缓冲**：如文件输出流`std::ofstream`，仅当缓冲区满或显式刷新时才输出（无`\n`自动刷新机制）

10. 讨论：**`\n`的缓冲区刷新行为**

> ### `\n`的**默认刷新行为**
>
> 在大多数 C++ 实现中，`std::cout`是**行缓冲**的 —— 当输出`'\n'`（换行符）时，会自动触发缓冲区刷新（即把缓冲区内容显示到控制台）。此时`'\n'`的效果与`std::endl`（“换行 + 显式刷新”）的 “刷新” 作用类似（但`std::endl`是**显式调用刷新**，而`\n`是行缓冲的**自动触发**）
>
> ### `std::ios::sync_with_stdio(false)`的干扰
>
> 若代码中执行了 `std::ios::sync_with_stdio(false)`，会**关闭 C++ IO 流（如`std::cout`）与 C 标准 IO（如`printf`）的同步**（常用于提升 IO 性能）。此时，`'\n'`的 “自动刷新” 行为可能失效 ——`\n`仅完成 “换行”，不再触发缓冲区刷新，需要显式用`std::flush`或`std::endl`才能强制刷新
>
> ### 输出目标的影响（重定向 / 管道场景）
>
> 当输出**不直接到控制台**时（比如通过管道 `| cat` 把程序输出传递给其他程序，或输出到文件），标准输出的缓冲模式可能从 “行缓冲” 变为 **“全缓冲”**。此时，`'\n'`不再触发刷新，缓冲区只有在 “满了” 或被**显式刷新 **（如`std::endl`/`std::flush`）时，才会把内容写入目标（文件 / 管道）
>
> 简言之，`\n`是否触发缓冲区刷新，取决于两个关键因素：**是否关闭了 IO 同步**（`std::ios::sync_with_stdio`），以及**输出目标是控制台还是文件 / 管道**

11. `cerr`：用于输出错误（无缓冲），输出内容会立即显示（不经过缓冲区），适合紧急错误信息的即时反馈

12. `clog`：用于非关键事件的日志记录（有缓冲）

13. `std::ofstream`是输出文件流的类型，作为一种向文件写入数据的方式，它使用`<<`插入运算符来将数据发送到文件。下面是一些你应当了解的方法： 

    | 方法        | 作用                 |
    | ----------- | -------------------- |
    | `is_open()` | 检查文件是否成功打开 |
    | `open()`    | 打开文件             |
    | `close()`   | 关闭文件             |
    | `fail()`    | 检查文件操作是否失败 |

14. 常见的文件打开模式：

```c++
// 基本模式：
std::ios::in      // 读取模式（默认用于ifstream）
std::ios::out     // 写入模式（默认用于ofstream）
std::ios::app     // 追加模式，写入总是在文件末尾
std::ios::ate     // 打开时定位到文件末尾，但可以移动到其他位置
std::ios::trunc   // 截断模式，清空文件内容（默认用于ofstream）
std::ios::binary  // 二进制模式，不进行文本转换
  
// 组合使用（用 | 操作符）
// 读写模式
std::fstream file("data.txt", std::ios::in | std::ios::out);

// 二进制追加模式
std::ofstream file("data.bin", std::ios::app | std::ios::binary);

// 读写 + 截断模式
std::fstream file("data.txt", std::ios::in | std::ios::out | std::ios::trunc);
```

15. 输入流的类型为std::istream，是一种从目标/外部源读取数据的方式，使用>>提取运算符进行读取，而std::cin是控制台输入流（console input stream）
16. std::cin是带缓冲的，可视为一个用户能存储数据并从中读取的地方，其缓冲区遇到空白字符即空格（" "）、换行符（\n）和制表符（\t）时停止，`std::cin` 读取模式如下：

| 读取数字   | 读取到非数字字符停止     | **不消耗分隔符**（换行符留在缓冲区） | **自动跳过所有前导空白字符**（空格、制表符、换行符） |
| ---------- | ------------------------ | ------------------------------------ | ---------------------------------------------------- |
| 读取字符串 | 读取到下一个空白字符停止 | **不消耗尾随分隔符**                 | **自动跳过所有前导空白字符**（空格、制表符、换行符） |

> 注：  `>>` 运算符会跳过前导空白但不消耗尾随分隔符，而 `getline()` 会读取并消耗换行符，因此两者混用时，需要手动清理缓冲区中的分隔符，或者，进一步说，你不应该将 getline () 和 std::cin 一起使用，因为它们解析数据的方式存在差异：std::cin 会将换行符留在缓冲区中，而 getline () 会清除换行符

17. 核心要点：

> 流（Streams）是程序中用于读写数据的通用接口。
>
> 针对同一源 / 目标类型的输入流与输出流是相辅相成的！
>
> 不要将 getline () 和 std::cin 一起使用，除非你实在迫不得已！
