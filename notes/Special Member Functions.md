# Special Member Functions

## 一、核心回顾与特殊成员函数概述
### 1. 前置知识补充
- 运算符重载回顾：非成员重载更灵活（支持非类类型左操作数、对称性比较），需访问私有成员时可通过`friend`关键字授权；成员重载直接访问类成员，但左操作数必须是当前类对象。
- 关键铺垫：类的默认行为由编译器自动生成的“特殊成员函数”控制，共6个，仅在被调用且未显式定义时生成。

### 2. 6个核心特殊成员函数（SMFs）
| 函数类型               | 语法格式                          | 核心作用                                  | 触发场景                                  |
|------------------------|-----------------------------------|-------------------------------------------|-------------------------------------------|
| 默认构造函数（Default Constructor） | `T()`                             | 无参数创建对象，初始化成员变量            | `Widget w;`、`Widget w{};`（无参数初始化） |
| 析构函数（Destructor）             | `~T()`                            | 对象生命周期结束时清理资源（如释放内存）  | 对象出作用域、delete调用时                |
| 拷贝构造函数（Copy Constructor）   | `T(const T&)`                     | 基于已有对象创建新对象（成员逐一拷贝）    | `Widget w2 = w1;`、`Widget w2(w1);`       |
| 拷贝赋值运算符（Copy Assignment）  | `T& operator=(const T&)`          | 已有对象赋值为另一个已有对象的副本        | `w1 = w2;`（两对象均已构造）              |
| 移动构造函数（Move Constructor）   | `T(T&&)`                          | “窃取”已有对象（通常是临时对象）的资源    | 临时对象初始化新对象（如函数返回值）       |
| 移动赋值运算符（Move Assignment）  | `T& operator=(T&&)`               | 已有对象“窃取”另一个对象的资源            | `w1 = 函数返回的临时对象;`                |

- 核心特点：编译器默认生成“成员逐一拷贝/赋值”的实现，无需手动编写，但动态内存场景下可能失效。

## 二、拷贝构造函数与拷贝赋值运算符
### 1. 默认行为：浅拷贝（Member-wise Copy）
- 定义：编译器自动生成的拷贝逻辑，逐一对类的成员变量进行拷贝（如int直接复制值，指针复制地址）。
- 适用场景：类无动态内存（无指针、无堆分配资源）时，浅拷贝足够安全（如仅含`int`、`std::string`成员的类）。
- 致命缺陷：含指针/动态内存时，拷贝后两个对象的指针指向**同一内存地址**，导致：
  1. 一个对象修改内容会影响另一个；
  2. 对象析构时重复释放同一内存（程序崩溃）。

### 2. 解决方案：深拷贝（Deep Copy）
- 定义：自定义拷贝逻辑，为新对象**重新分配独立内存**，并复制原对象的资源内容，而非仅复制指针地址。
- 示例：`Vector<T>`的深拷贝实现（修复浅拷贝问题）
  ```cpp
  // 拷贝构造函数（深拷贝）
  template <typename T>
  Vector<T>::Vector(const Vector<T>& other) 
    : _size(other._size), _capacity(other._capacity), _data(new T[other._capacity]) {
    // 逐元素复制内容，而非复制指针
    for (size_t i = 0; i < _size; ++i) {
      _data[i] = other._data[i];
    }
  }
  
  // 拷贝赋值运算符（深拷贝，需先释放自身资源）
  template <typename T>
  Vector<T>& Vector<T>::operator=(const Vector<T>& other) {
    if (this == &other) return *this; // 避免自赋值
  
    // 释放自身原有内存
    delete[] _data;
  
    // 重新分配内存并拷贝内容
    _size = other._size;
    _capacity = other._capacity;
    _data = new T[_capacity];
    for (size_t i = 0; i < _size; ++i) {
      _data[i] = other._data[i];
    }
    return *this;
  }
  ```

### 3. 拷贝构造 vs 拷贝赋值
| 对比维度       | 拷贝构造函数                          | 拷贝赋值运算符                          |
|----------------|---------------------------------------|-------------------------------------------|
| 核心区别       | 初始化**新对象**（对象不存在）        | 赋值给**已有对象**（对象已构造）          |
| 触发语法       | `Widget w2(w1);`、`Widget w2 = w1;`   | `w1 = w2;`（w1、w2均已存在）              |
| 自赋值处理     | 无需（新对象不可能是自身）            | 必须处理（避免释放自身内存后无法拷贝）    |

## 三、禁用特殊成员函数：`delete`关键字
### 1. 核心作用
显式禁用编译器默认生成的特殊成员函数，阻止特定操作（如拷贝、赋值）。

### 2. 语法与示例
```cpp
class PasswordManager {
public:
  PasswordManager() {} // 默认构造函数（允许创建对象）
  ~PasswordManager() {} // 析构函数（清理资源）

  // 禁用拷贝构造和拷贝赋值，防止密码数据被复制
  PasswordManager(const PasswordManager& rhs) = delete;
  PasswordManager& operator=(const PasswordManager& rhs) = delete;
};
```

### 3. 应用场景
- 禁止拷贝：如`PasswordManager`（敏感数据）、`std::unique_ptr`（独占指针，仅允许移动）；
- 限制操作：仅允许移动不允许拷贝，或禁用默认构造（强制使用带参数构造函数）。

## 四、移动语义：移动构造与移动赋值运算符
### 1. 核心动机：避免不必要的拷贝
- 问题：临时对象（如函数返回值、表达式结果）的拷贝会浪费资源（如复制大数组、大字符串），拷贝后临时对象即被析构，拷贝操作毫无意义。
- 目标：“窃取”临时对象的资源（如指针指向的内存），而非复制，提升效率。

### 2. 关键概念：右值引用（Rvalue Reference）
- 语法：`T&&`，专门绑定临时对象（右值），表示“可被移动的对象”。
- 区别：左值（`T&`）是可被取地址的持久对象（如`w1`），右值是不可持久的临时对象（如`func()`的返回值）。

### 3. 移动构造函数
#### （1）语法与实现
```cpp
template <typename T>
Vector<T>::Vector(Vector<T>&& other) 
  : _size(other._size), _capacity(other._capacity), _data(other._data) {
  // 关键：将原对象的指针置空，避免析构时重复释放
  other._data = nullptr;
  other._size = 0;
  other._capacity = 0;
}
```

#### （2）核心逻辑
- 窃取`other`的资源（`_data`指针），而非复制；
- 原对象（`other`）需置为“可析构状态”（指针为空、大小为0），避免析构时释放已被窃取的资源。

### 4. 移动赋值运算符
#### （1）语法与实现
```cpp
template <typename T>
Vector<T>& Vector<T>::operator=(Vector<T>&& other) {
  if (this == &other) return *this; // 避免自赋值

  delete[] _data; // 释放自身原有资源

  // 窃取other的资源
  _data = other._data;
  _size = other._size;
  _capacity = other._capacity;

  // 重置other
  other._data = nullptr;
  other._size = 0;
  other._capacity = 0;

  return *this;
}
```

### 5. 触发场景
- 临时对象初始化新对象：`Vector<int> v = func_return_vector();`（`func_return_vector()`返回临时对象）；
- 强制移动：通过`std::move()`将左值转为右值：`Vector<int> v2 = std::move(v1);`（`v1`资源被窃取，变为空状态）。

## 五、实践原则：零规则与三规则
### 1. 零规则（Rule of Zero）
- 核心思想：若类的成员变量均为“自管理类型”（如`std::string`、`std::vector`，已实现完整SMFs），则无需自定义任何特殊成员函数，直接使用编译器默认生成的即可。
- 示例：
  ```cpp
  class StringWithId {
  private:
    int id;
    std::string str; // std::string已实现深拷贝、移动语义
  };
  // 无需自定义拷贝、移动、析构函数，编译器默认实现足够安全
  ```

### 2. 三规则（Rule of Three）
- 核心思想：若需自定义**析构函数**（通常是手动管理动态内存），则必须同时自定义**拷贝构造函数**和**拷贝赋值运算符**，避免浅拷贝导致的内存问题。
- 原因：自定义析构函数意味着需手动释放资源，编译器默认的浅拷贝会导致多个对象共享资源，析构时重复释放。

## 六、关键区分：初始化方式与SMF调用
| 代码示例                  | 触发的特殊成员函数          | 备注                                  |
|---------------------------|-----------------------------|---------------------------------------|
| `Vector<int> v1;`         | 默认构造函数                | 无参数初始化                          |
| `Vector<int> v2(v1);`     | 拷贝构造函数                | 用已有对象初始化新对象                |
| `Vector<int> v3 = v1;`    | 拷贝构造函数                | 等价于`v3(v1)`，非赋值运算符          |
| `v1 = v2;`                | 拷贝赋值运算符              | 已有对象赋值                          |
| `Vector<int> v4 = func();`| 移动构造函数                | `func()`返回临时对象（右值）          |
| `v1 = std::move(v2);`     | 移动赋值运算符              | `std::move(v2)`将v2转为右值            |
| `Vector<int> v5(3);`      | 自定义构造函数（非SMF）     | 带参数的非特殊构造函数                |
| `Vector<int> v6{};`        | 默认构造函数（列表初始化）  | C++11后的统一初始化语法                |

## 七、核心总结
### 1. 特殊成员函数核心价值
- 编译器默认生成基础实现，覆盖简单场景；
- 动态内存场景需自定义深拷贝（避免浅拷贝问题）；
- 移动语义通过“窃取资源”提升效率，避免临时对象拷贝浪费；
- `delete`关键字可灵活禁用特定操作（如拷贝）。

### 2. 实践关键要点
- 优先遵循“零规则”：依赖自管理成员（`std::string`、`std::vector`），无需自定义SMFs；
- 动态内存场景遵循“三规则”：自定义析构时必须自定义拷贝构造和拷贝赋值；
- 移动语义仅适用于“可被窃取资源”的对象，移动后原对象需保持可析构状态；
- `std::move()`不触发移动，仅将左值转为右值，真正触发移动的是移动构造/赋值函数。
